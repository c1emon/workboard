# Proposal

状态：已在 `codex/refine-operation-plan-workflows` 实施，验证结果见 [tasks.md](tasks.md)。完整需求及说明见 [requirements.md](requirements.md)，可验证要求见本 change 的 delta specs。

## Why

操作周期生成需要用户手算周期零点，重新定位后又可能残留旧的待处理实例。大屏空间仅适合一条操作时间轴，同时操作与巡视计划缺少所需的文件导入导出能力。

## What Changes

- 周期性操作实例生成可选择起始子任务及其实际开始时间；一次性计划仅从周期零点生成，不修改计划定义。
- 保留非稠密周期空档及原有周末、节假日规则；生成只要求任务开始时间严格早于截止时间，跨越截止时间的任务保留完整时长。
- **BREAKING**：重新生成改为替换该操作计划全部未开始的自动安排，包含新生成范围之外的旧待处理实例；继续保留进行中等受保护实例。
- 多个操作计划继续存在，由管理端独立单选大屏展示的计划；首次默认第一个，全局持久保存，切换后立即刷新，无展示内容时显示 `无可展示计划`。
- 操作和巡视计划增加单计划 `.xlsx` 导出，包含基本信息、全部明细及表尾扩展列；操作计划增加覆盖指定已有计划子任务明细的 `.xlsx` 导入。
- 导入导出尽量保持一致，但不强制支持直接回导。
- 导入保留计划基本信息，不自动修改已生成实例。

## Capabilities

### New Capabilities

- `operation-instance-generation`：操作周期的子任务起点定位、整体替换和实例保护。
- `operation-board-selection`：管理端单选大屏展示的操作计划。
- `plan-file-exchange`：操作与巡视计划导出，以及覆盖已有计划明细的导入。

### Modified Capabilities

- `board-log-presentation`：将旧的任务文字撑高要求更新为当前确认的固定行高、两行截断与原滚动方式；不改变业务页面布局。

## Impact

- 预计涉及后端生成规则、计划文件接口、看板操作数据筛选及展示选择存储。
- 预计涉及管理端生成表单、展示选择和计划导入导出入口，以及相应测试。
- 产品规则已明确；接口、存储及文件工作表布局等实现设计留给后续 design，不在本轮编写业务代码。
- 实施已完成；本 change 尚未归档，未部署至共享环境。
