# Design

状态：设计文档，尚未实施。本轮不修改业务代码、不运行 apply、不切换实现分支。

## Context

动机与范围见 [proposal.md](proposal.md)，产品决定见 [requirements.md](requirements.md)。Web UI 的布局、文案、字段、交互和验收样例统一见 [ui-design.md](ui-design.md)，实施时不得临时另设计一套流程。

现有前端为 Vue 3，管理页面由 `AdminView`、模块组件和 composables 组成；后台为 Fastify、SQLite，写操作后通过现有 SSE 通知看板更新。管理端使用浅色列表与弹窗，操作模块有按日期筛选和“显示全部”，巡视模块有“任务实例 / 巡视模板”两个标签。

## Goals / Non-Goals

**Goals:**

- 将新能力放入现有操作和巡视模块，明确每次动作的目标计划。
- 区分计划编辑、本次实例生成、大屏展示选择和文件交换四类状态。
- 让覆盖行为、请求状态和失败结果可见，避免误把重新生成当成局部补充。
- 为实现和验证提供固定的 UI 约定，详见 ui-design 的验收清单。

**Non-Goals:**

- 不重做全站视觉、导航和其他管理模块，不引入新的组件库、状态管理库或在线字体。
- 不增加多计划批量生成、批量导出、生成批次管理或大屏轮播。
- 不把预览扩张为完整排程模拟器；不新增独立预览服务。
- 不新增鉴权、原始扩展 JSON 编辑器或文件直接回导保证。

## Decisions

### 1. 展示选择使用全局独立设置

以服务端持久化的全局操作计划 ID 为展示选择，不复用 `enabled`，不存入浏览器 localStorage。首次初始化按现有全量管理列表顺序选第一个；之后失效不自动换选。读取结果应足够显示已选计划名称、是否存在及启用状态，即使该计划被当前日期筛选隐藏。

切换选择仅在服务端保存成功后更新管理端单选状态并发布现有 SSE 事件。大屏按选择筛选操作实例；计划禁用、被删除或窗口内没有实例时显示约定空态。选择的保存与计划启用状态保持独立。

替代方案：复用启用开关会把“可生成”和“用于展示”混在一起；前端本地存储无法保证多块大屏一致，均不采用。

### 2. 生成是单计划、有事务边界的替换操作

生成表单提交目标计划、实际开始时间、截止时间，以及周期性计划的起始子任务。一次性计划仅允许周期零点。服务端在计划定义不变的前提下定位本次周期，保留空档、现有日历跳过规则和完整任务时长，按开始时间严格早于截止时间筛选。

重新生成在一次事务内清除目标计划所有符合条件的旧待处理自动实例，并写入新安排；保留已有受保护实例及生成标识去重。不增加禁止时间重叠的校验。事务提交后再通知大屏。

生成返回清理、新增、跳过的实际数量，供成功反馈使用；不为确认页另建逐实例预览接口。原“全部操作计划”选项不适合指定某个子任务起点的流程，新的操作生成 UI 不提供它。

### 3. 文件交换分为完整单计划导出和明细覆盖导入

一次导出一个计划，XLSX 内使用“计划信息”和对应“子任务”或“周期项”两个工作表。固定明细列在前，扩展键逐列追加在后。格式细则与界面入口见 ui-design。

导入始终先选择已有计划，校验文件后展示目标、替换数量及有限预览，再确认覆盖。只替换明细，计划基本信息、大屏选择和已生成实例不变。操作导入和现有巡视导入复用同一反馈流程，不发展成全局文件中心。

替代方案：自动新建计划、按名称合并或把导入和重新生成合成一个按钮，会扩大副作用，不采用。

### 4. UI 状态按动作隔离

大屏选择保存、生成、导入、导出分别有独立请求状态。沿用 composables 管理状态、组件承载展示的结构，不因本次需求引入 Pinia 或表单库。列表加载采用最后一次请求结果，关闭弹窗或切换目标后不回写过期结果。

同一计划的生成、导入和编辑提交期间互斥；导出只读取已保存数据。可取消的阶段和写入中的阶段在 ui-design 中分别规定。现有全局同步状态只作为摘要，错误同时出现在触发动作附近。

## Risks / Trade-offs

- [短范围生成会清除更远期的旧安排] → 表单和确认页都明确“全部未开始的自动安排”，成功反馈清理与新增数量。
- [列表筛选隐藏当前展示计划] → 当前选择摘要始终独立显示，不根据当前列表推断全局选择或重新设置默认值。
- [文件写入或实例生成请求超时，客户端无法确定结果] → 显示“结果未确认”，不自动重试写入、不保证原数据未变；明确失败且事务已回滚时才提示原数据保留。
- [菜单被表格横向滚动容器裁切] → 菜单浮层放在不受表格 overflow 裁切的位置，并按视口边界调整展开方向。
- [扩展列与固定列同名] → 固定表头保持稳定，扩展列增加“扩展：”前缀直至名称唯一，保留字段含义，不产生重复表头。
- [导入替换明细后已生成实例仍是旧内容] → 导入成功提示实例未变，由用户单独重新生成；不暗中联动生成。
- [旧正式展示规范仍描述行高撑开] → 本次按用户确认保留现有固定行高、两行截断和滚动；补充该规范的 delta，避免文档与本轮布局约束冲突。

## Migration Plan

本轮只交付规范与设计文档，不运行数据库迁移、不发布应用。后续实施需先完成 tasks，按仓库规则确认实现分支。

实施时，现有计划与实例继续保留；新增的展示选择在首次初始化时确定，不在每次启动或读取时覆盖。生成替换语义与确认文案必须一起发布，防止旧文案掩盖新的清理范围。功能回退不得假定能够恢复已成功替换的旧待处理实例；事务只保证单次失败回滚。
