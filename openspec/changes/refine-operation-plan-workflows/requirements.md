# 操作与巡视计划需求记录

记录日期：2026-10-25。

状态：本轮产品规则已确认，尚未实施。本轮仅记录需求，不代表批准实施。暂不修改业务代码、数据库或大屏布局。

## 1. 周期任务生成

### 用户提出的方向

- 稠密与非稠密周期任务放在一起考虑。
- 保留计划定义，通过本次生成规则指定从周期的哪个位置开始，不修改计划起点或子任务定义。
- 有限循环、无限循环计划不强制从周期相对零点开始生成；选择起始子任务，输入该子任务的实际开始时间，避免用户手工反推周期零点。
- 一次性计划只能从本轮周期零点开始，输入时间作为本轮零点时间，不提供任意子任务起点选择。
- 不提供“已进入子任务多久”或额外偏移输入；输入的时间就是所选子任务的起点。
- 生成从所选子任务开始，并继续循环。

示例：选择操作 B，输入 10 月 25 日 10:30，表示本次生成的 B 从该时刻开始，不表示 B 此时已经执行了一段时间。

### 已确认的实例更新规则

- 一个操作计划只维护一套任务实例安排，不为每次生成并存多套安排。
- 重新生成时，先移除该计划旧的、来源为自动生成、状态为待处理且尚未开始的实例，再填入按本次规则生成的新实例。
- 旧待处理生成实例的清理按计划进行，不仅限于与本次生成日期窗口重叠的实例，避免窗口外遗留旧的未来安排。
- 即使本次生成范围缩短，也会清除该计划在新范围之外的旧待处理生成实例。例如本次仅生成未来三天，原第四天及之后的旧待处理生成实例同样移除。
- 进行中、已完成、已取消、人工录入和人工调整的实例继续保留。
- “一套安排”指当前后续安排唯一；保留历史记录及受保护实例不视为并存另一套未来安排。
- 界面应明确提示“替换该计划全部未开始的自动安排”，避免被理解为仅补充或刷新所选日期范围。
- 删除旧实例和写入新实例应作为一次原子操作，生成失败时保留原安排。

### 已确认的生成边界

- 非稠密周期的空档按原计划保留，不压缩间隔。
- 周期性计划从 B 开始时，本轮只生成开始时间不早于 B 起点的子任务；早于 B 开始但仍与 B 重叠的子任务不补生成。后续完整轮次继续正常循环。
- 截止时间只约束任务开始时间：开始时间必须严格早于截止时间；符合条件的任务保留完整时长，即使结束时间超过截止时间。开始时间等于截止时间时不生成。
- 周末、节假日及调休工作日规则沿用原有逻辑，不因这次调整改变跳过语义。

### 实例重叠说明

- 先前提到的“冲突”仅指新安排可能与保留的进行中等实例发生时间重叠。时间重叠不必然是业务错误，现有计划本身允许子任务重叠，因此不额外引入禁止重叠的校验。
- 对保留实例仍沿用生成标识去重，避免对同一实例重复插入；不能因时间相交而自动删除受保护实例。

## 2. 大屏操作时间轴选择

### 已明确的需求方向

- 允许多个操作计划同时存在，并继续在管理端维护。
- 在后台单选大屏展示哪一个操作时间轴。
- 大屏只展示被选中的一条时间轴，不增加多轨展示或计划轮播。
- 保持其他大屏模块的位置与尺寸不变。
- 展示选择只控制大屏内容，不以删除其他计划来实现单选。
- 展示对象按操作计划选择；重新生成更新该计划的唯一后续安排，不引入按生成批次选择大屏的模式。

### 已确认的展示规则

- 大屏展示选择独立于计划启用、禁用状态；切换展示计划不修改计划启用状态，禁用计划也不自动改选另一个计划。
- 首次使用且存在计划时，默认选择管理列表既有顺序中的第一个计划。
- 无选择、所选计划被禁用或删除、当前展示时间范围内没有可展示实例时，大屏操作区显示 `无可展示计划`，不自动改选其他计划。
- 展示选择全局持久保存，刷新页面或重启后仍保留。切换后立即通知所有大屏刷新，不等待兜底轮询。

## 3. 计划导入与导出

### 已明确的能力范围

- 操作计划增加导出能力。
- 巡视计划增加导出能力。
- 操作计划增加导入能力。
- 这些能力与周期生成、大屏展示选择一起纳入本轮需求讨论，暂不实施。

### 已确认的导入规则

- 沿用现有巡视周期项导入的覆盖方式：先选择一个已有计划，校验导入文件，确认后整体替换该计划的子任务/周期项。
- 操作计划导入不新增计划，不按名称匹配或合并，不追加到现有子任务之后。
- 保留所选计划的名称、说明、起点等基本信息，不因导入而改写这些字段。
- 导入不修改已生成的任务实例；实例仍通过独立的生成操作更新。

### 已确认的文件规则

- 导入、导出统一采用 Excel（`.xlsx`）。
- 导出按单个计划进行，不提供全局导出或批量导出。
- 导出内容为所选计划基本信息和全部子任务/周期项明细，不包含已生成实例和执行状态。
- 导出与导入的字段和布局在可行时尽量保持一致，但不强制支持导出文件直接回导，也不把直接回导作为必须满足的验收条件。
- 扩展字段按字段名直接罗列在子任务/周期项明细的固定列之后，即表尾追加扩展列。
- 导入先校验文件，再写入；任何必需字段、表头或时间规则不符合要求时，不部分覆盖原计划。
- 导入计划与生成实例分开操作，不因导入文件而自动替换现有任务实例或改变大屏当前选择。

## 4. 当前实现事实

- 看板后端将时间范围内的操作实例合并返回，没有只取第一个计划。
- 大屏将全部操作实例放在同一条时间轴，没有按计划分组，且关闭了任务堆叠。
- 当前操作区未预留多条时间轴的空间，重叠任务可能互相遮挡。
- 看板返回的操作项目前不包含计划 ID 或计划名称。
- 操作周期以计划起点和子任务相对偏移定位；现有刷新入口没有本次生成的子任务起点选择。
- 现有操作实例通过“计划 ID + 子任务 ID + 该轮周期起点”匹配，管理端刷新会传入 `refreshPending: true`。
- 匹配到的实例只有在来源为自动生成、状态为待处理时才更新；人工实例、人工调整实例及进行中、已完成、已取消实例均保留。
- 匹配不到时新增实例；重新生成不会清理旧实例，也不会清理因模板变化而不再生成的实例。
- 如果重新定位导致周期起点及生成键改变，新实例会被新增，旧实例仍保留，可能出现新旧安排并存。
- 生成键中的周期起点是每一轮的实际起点，用于区分同一子任务在不同轮次的实例。仅改变生成日期窗口仍按原周期定位；周期对齐一致时，重叠窗口内会匹配同一批实例。重新指定起点且改变周期对齐时，重叠时间范围可能出现两套实例。
- 巡视管理已有 Excel 周期项导入，当前采用覆盖指定巡视计划全部周期项的方式。

## 5. 本轮边界

- 仅讨论并记录需求，不开始实施、不迁移数据、不创建或切换实现分支。
- 暂不把待确认事项转换为既定实现方案，也不预建生成批次等新模型。
- 继续保留此前确定的现有表格滚动方式；鉴权不在本项目本轮需求范围内。
